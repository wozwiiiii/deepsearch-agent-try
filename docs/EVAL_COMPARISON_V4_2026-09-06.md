## TL;DR

- **总分 40/45（88.9%，v3）→ 41/45（91.1%，v4）**。四类中三类满分（routing 6/6、web 10/10、multi 7/7）。
- **守卫战绩再创新高：7 次触发、7 次全部救回**（过渡语 1 次 + 空输出 6 次），其中 route-06 在 429 退避间隙内两次触发守卫并最终完成。
- **route-04 首次 PASS**：模型正确调用 Markdown 生成工具（P2 硬约束放行合法文件请求，双向验证完成）。
- sql 类 18/22 波动 −3：4 条 FAIL 全部定性为模型行为波动/字符级偏差（逐条如实分析见下），无基础设施污染。
- 污染仅 1 条：route-06（Tavily 代理故障下"PASS 但 result 为空"的脏通过，已标记）。
- 三轮曲线：v2 36/45（80.0%）→ v3 40/45（88.9%）→ **v4 41/45（91.1%）**。

## route-04 首次 PASS（P2 硬约束双向验证完成）

模型正确调用 Markdown 文档生成工具生成周报（26,972 tokens）——合法文件请求被 `file_intent_guard` 放行。至此"劫持治理"闭环：v2 的 hijack 残留场景（web-07 未要求文件→不生成）与合法请求场景（route-04 要求文件→生成）双双按预期工作。

## 如实报告：sql 类 4 条 FAIL 逐条定性（均无污染）

| 用例 | 现象 | 定性 |
|------|------|------|
| sql-02 | 答"阿托伐他汀钙"，期望"阿托伐他汀钙片"——**实质正确，少一个"片"字**（与 v3 sql-19"替诺福酯"同类字符级偏差）。附带发现：回答中复述了"本次查询没有生成文件，因为用户并没有要求生成任何形式的文件或报告"——提示词/守卫引导语被模型过度复述进了最终回答，属表达瑕疵不影响数据正确性 | 字符级偏差 |
| sql-10 | 声称"没有找到上海华山医院采购布洛芬的记录"（记录实际存在，期望 5000） | 查询未命中（行为波动） |
| sql-12 | 给出批次详情但通用名处写"未提供，可根据 ID 进一步查询"——未做 drugs 表 join 补全 | 查询不完整（行为波动） |
| sql-18 | 答总库存 94,000，DB 真值 47,000（查询口径错误，疑重复计入） | 查询口径错误 |

定性依据：4 条均为数据/查询层问题，与守卫、退避、硬约束无因果关联；sql 批处于 429 高压窗口（5 条触发退避），限流压力与模型波动相关性如实记录但 n 不足以归因。

## 结论

1. **守卫体系（过渡语 + 空输出）经 v4 实战确认成熟**：累计 9 次触发（v3 2 次 + v4 7 次）全部救回。
2. **文件生成治理闭环**：route-04 首次 PASS + web-07 持续 PASS。
3. sql 类是剩余波动的主要来源（查询口径/完整性/字符偏差三类），判定均为真实 FAIL、无系统性缺陷——若要继续提升，方向是用例侧（期望值别名归一）与提示词侧（通用名带剂型后缀的强约束），收益有限、列为低优先级。
4. 项目质量体系进入稳定态：**四类评测中三类满分，总分 91.1%**。下一主攻块回到 **P0-2 任务出进程**（部署架构 0/1 → 1/1，4–6 天）。
